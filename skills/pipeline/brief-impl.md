# Implementer brief (shared)

- First `git -C <worktree> rebase main` if the worktree is clean and behind main.
- Read requirements.md and plan.md yourself (fix rounds: also fixes-<n>.md).
- Create the progress file named in your prompt first (none named: the report path with `.md` replaced by `.progress.md`); update it at each step.
- Leave the change UNCOMMITTED in the worktree, even if a general instruction says to commit after each change. The orchestrator commits at merge (wt-merge.sh).
- Write the report to the report path in your prompt (the final message may repeat it; run collectors read only the file). Report: changed files, verification commands with actual results, deviations from the plan (fix rounds: per finding FIXED/DISPUTED with the test and evidence it fails without the fix).
- Never `git stash` (the stash is shared across worktrees and sessions); to run old code, `git archive <rev> | tar -x -C "$(mktemp -d -t pipe-scratch)"` or a `cp -R` scratch copy made with `mktemp -d -t pipe-scratch` (under `$TMPDIR`, never `/tmp`). Delete your scratch directories (copies, target dirs, base builds) before you finish with a guarded `rm -rf -- "${SCRATCH:?}"`; a 2026-11-03 run left 158 GB behind. Only if that deletion is denied, leave it and name it in your report.
- Mutants run only in a `cp -R` scratch copy with its own `CARGO_TARGET_DIR` (a shared target dir leaves stale mutant builds behind), never in the worktree.
- Tests that touch process-global state (environment, statics, global registries, signal handlers) pass under a per-process runner such as cargo-nextest and fail under the default runner when they share a process. Isolate them the repo's way, and run the default runner (`cargo test -p <crate>`) once on any crate where you added one.
- Escapes: the Bash command text and the Write tool decode `\uXXXX` sequences, so a literal backslash-u written that way is silently lost. When a file or test must contain `\u`, `\k` or similar escapes, build the backslash at runtime (`chr(92)`, `printf '\\'`) and confirm the written file with `grep -F`.
- Timing-sensitive tests: a mutant counts as killed only if the test fails in every one of at least 12 runs, including a round of 12 concurrent runs. Report fails/runs, never a single sample (WP-163: an implementer's "fails 3/3" was 4/12 under review).
- Fresh worktree: before running tests that spawn the repo's binaries or helper builds, build them once (the profile or repo docs name the commands); a "binary not found, run cargo build" failure is a setup gap, not a test result (WP-165, WP-168 each lost a run to it). After any test filter (`nextest -E`, `-k`), check the summary ran more than 0 tests.
- Fix rounds: every product line the fix adds or changes needs a test that fails with that line reverted; run the revert as a mutant in your scratch copy and report it (WP-164 fix-1 added an untested memo-hit line; verify caught it and a second fix round followed).
- Fix rounds: when your fix departs from the fixes file's direction, or changes what a shared step produces (inserted escapes or markers, a helper's output, a format), list every place that reads that output, test each, and put the list in the report (WP-179 fix-1 escaped both brackets instead of the stated strip; image alt text, read from raw source, leaked the escapes; fix-2's brief asked for every reader and verify-2 shipped).
- Never remove an existing guard, check or branch as "no effect" without a test or probe row showing both versions agree on a case the guard covers; list every removal in the report (WP-200 fix-1 dropped an `!only_conv` guard as result-neutral; verify-1 found an upstream mismatch and a second fix round restored it). The same holds when a fix adds or restores a guard: name the cases its condition matches beyond the claim and pin one with a row (WP-200 fix-2 restored that guard over every node below the coerced object; verify-2 found 9 union-branch rows it broke, fix 3 scoped it to the coerced node).
